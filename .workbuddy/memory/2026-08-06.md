## 优化：`.author .create-time` 偶尔获取到 `--` 的问题

- **现象**：详情页发布时间由 JS 异步渲染，冷加载直链时 `.create-time` 先返回占位符 `--`，偶发读不到真实时间。
- **排查**：页面 HTML/内嵌 JSON 中无可靠绝对时间戳（币安帖子数据走独立 API，初始 HTML 不含 createTime；无 `<time datetime>`、无 datetime 属性）。但 `wait_until='networkidle'` 下冷加载 2s 即解析出真实相对时间 → 证实 `--` 是渲染延迟占位符。未用 networkidle（币安有长连 websocket，可能永不触发）。
- **修复**：新增 `get_create_time(page)` 轮询函数——读到 `--`/空就每 1.5s 重试，最多 5 次，拿到非 `--` 的有效相对时间即返回；始终 `--` 则返回原值（上层当「未知」跳过该帖）。详情页读取改为 `await asyncio.sleep(2)` + `get_create_time(page)`。
- **验证**：直接运行一轮，5 篇候选均解析出真实时间（4/8/11/3/6 小时），无 `--`，进程 RUNNING。
